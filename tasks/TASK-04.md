# 과제 4 — 코드: 완료한 할 일을 날짜별로 묶어 보여 주는 report 명령 추가

종류: 작은 기능 추가 (테스트는 미리 제공됨)
브랜치 이름: `task/04-report` (이 저장소의 운영 규칙 파일이 작업자 브랜치 이름을 따로 정해 두었다면 그 규칙을 따른다)

## 목표
할 일을 완료한 날짜를 기록하고, 완료한 할 일을 날짜별로 묶어 보여 주는 `report` 명령을 추가한다.

### 완료 날짜 기록
- 완료 처리한 항목에는 완료 날짜를 `doneOn` 필드에 `YYYY-MM-DD` 형식 문자열(예: `"2026-10-20"`)로 저장한다. 시각은 저장하지 않는다. 미완료 항목에는 `doneOn`을 두지 않는다.
- `done <번호> --date YYYY-MM-DD`: 그 날짜를 완료 날짜로 기록한다.
- `done <번호>`(`--date` 생략): 명령을 실행한 컴퓨터의 현지 시간대 기준 오늘 날짜를 기록한다. 현지 시간대는 환경 변수 `TZ`가 있으면 그것을 따른다.
- 이미 완료한 항목을 다시 `done` 하면 완료 날짜를 새 값으로 바꾼다(잘못 적은 날짜를 고치는 방법이다). `--date`를 생략하고 다시 `done` 하면 오늘 날짜로 바뀐다.
- `--date` 값이 `YYYY-MM-DD` 형식(네 자리 연도·두 자리 월·두 자리 일)이 아니거나 달력에 없는 날짜(예: `2026-02-29`, `2026-13-01`)이거나 값이 빠졌으면 exit 1로 끝나고, 표준 오류에 `YYYY-MM-DD`라는 글자를 포함한 이유를 출력한다. 이때 항목과 저장 파일은 바뀌지 않는다.
- `done`과 `list`의 출력 형식은 지금 그대로다(날짜를 덧붙이지 않는다).

### report 명령
- `src/report.js`를 새로 만들어 `formatReport(tasks)`를 export 한다. 할 일 배열을 받아 출력할 줄의 배열(문자열 배열)을 돌려준다. 입력 배열과 그 항목을 바꾸지 않는다.
- `src/cli.js`에 `report` 명령을 추가한다. 저장 파일을 읽어 `formatReport`의 결과를 한 줄씩 출력하고 exit 0으로 끝난다. 저장 파일을 만들거나 바꾸지 않는다.
- 출력 형식(완료 항목이 있을 때):

```
2026-10-20 (2개)
  [x] 1 우유 사기
  [x] 3 빨래
2026-10-22 (1개)
  [x] 4 청소
날짜 없음 (1개)
  [x] 5 예전에 끝낸 일
```

- 완료(`done: true`)인 항목만 넣는다. 미완료 항목은 `doneOn`이 있어도 넣지 않는다.
- 묶음 머리줄은 `<날짜> (<개수>개)`이고, 날짜 오름차순으로 놓는다. 각 묶음 안의 항목은 번호 오름차순이며, 줄 앞에 공백 두 칸을 두고 기존 한 줄 표시 형식(`[x] 1 우유 사기`)을 쓴다.
- 날짜는 저장된 `YYYY-MM-DD` 문자열 그대로 묶고 표시한다. 실행하는 컴퓨터의 시간대가 달라도 같은 파일이면 출력이 같아야 한다.
- `doneOn`이 없는 완료 항목(이 과제 전에 만든 저장 파일)은 맨 뒤의 `날짜 없음 (<개수>개)` 묶음에 넣는다. 그런 항목이 없으면 이 묶음은 출력하지 않는다.
- 완료 항목이 하나도 없으면(저장 파일이 없을 때 포함) `(완료한 할 일 없음)` 한 줄을 출력한다.

검증 테스트는 `tasks/tests/task04.test.js`에 이미 있다. 구현 전에는 실패하고(`src/report.js`가 없으므로 import 단계에서 오류), 구현 후에는 통과해야 한다. 테스트는 날짜를 고정값으로 주거나 시간대를 고정한 자식 프로세스로 확인하므로, 언제 어느 시간대에서 돌려도 결과가 같아야 한다.

다음은 이 과제에서 정하지 않으며 테스트도 보지 않는다: 연도 `0000`~`0099`인 날짜의 처리, `--date`를 번호 앞에 두거나 `--date=값` 형태로 쓴 경우, `--date`와 번호가 동시에 잘못됐을 때 어느 오류를 먼저 알릴지, 저장된 `doneOn`이 빈 문자열이거나 문자열이 아닌 경우.

## 수락 기준
1. `npm run test:task04`가 exit 0이다.
2. `npm test`와 `npm run check`가 계속 exit 0이다.
3. README.md의 "기능 지도" 표에 `완료 항목 날짜별 보고 | src/report.js | formatReport | npm run test:task04` 행이 추가돼 있다.
4. README.md의 "명령 사용법" 절에 `report` 명령이 한 줄 추가돼 있고, `done` 줄에 `--date YYYY-MM-DD`를 쓸 수 있다는 것이 적혀 있다.
5. 잘못된 명령일 때 표준 오류에 나오는 사용법 안내(`src/cli.js`)에 `report`와 `--date`가 들어 있다.
6. Node 20에서도 동작한다(CI가 Node 20으로 돈다). Node 21 이상 전용 API를 쓰지 않는다(CI는 `test:task04`를 돌리지 않으므로 작업자나 검수자가 코드를 읽어 확인한다).

## 검증 명령
```
npm run test:task04
npm test
npm run check
```
세 명령 모두 exit 0이면 통과다.

## 금지 사항
- `tasks/tests/task04.test.js`는 수정하지 않는다.
- `test/` 아래 기존 테스트를 수정하거나 지우지 않는다.
- 새 의존성(package.json의 dependencies/devDependencies)을 추가하지 않는다.
- 저장 파일의 기존 형식(`nextId`, 항목의 `id`·`text`·`done`)을 바꾸지 않는다. 예전 저장 파일도 그대로 읽혀야 한다.
- 이 과제와 무관한 파일(`src/stats.js`, 다른 과제 파일)은 건드리지 않는다.
- `done` 외 명령에 `--date`를 붙였을 때의 동작은 이 과제에서 정하지 않는다. 그것을 위해 다른 명령을 바꾸지 않는다.
